1. Executive Summary & Problem Statement

⚠️ Existing Industry Problems
  • Black-Box Actuarial Quotes: Traditional health insurance quotes provide customers with a single cost figure without explaining why high premiums are charged.
  • Opaque Risk Factors: Customers cannot see how specific vitals (BMI, blood pressure, smoking) mathematically impact their annual quote.
  • Free-Tier Hosting Sleep (Render 502 Errors): Cloud services like Render Free enter sleep mode after inactivity. Initial API calls fail with 502/503 errors if cold starts are unhandled.
💡 Existing Market Solutions vs. Our Innovation
  • Static Actuarial Lookup Tables: Hardcoded linear rules that fail to capture non-linear feature interactions (e.g. combined risk of high BMI + smoking).
  • Manual Render URL Pings: Users previously had to manually visit backend URLs to wake up sleeping services.
  • Our Solution (InsureWise AI): Automated, robust cold-start retry architecture paired with explainable XGBoost ML and real-time SHAP cost attributions.

2. What We Are Solving

  1. Transparent & Explainable AI Pricing: Decomposes annual premium quotes into exact dollar attributions ($+/$-) for 20 demographic and medical features using game-theoretic SHAP values.
  2. Zero-Cost Free-Tier Cold-Start Handling: Implements an automated, bounded 15-attempt retry loop on the Node.js backend to seamlessly wake up sleeping Render ML services without user intervention.
  3. Enterprise PDF Quote Export: Enables users to instantly export full actuarial audit reports as clean PDF documents.

3. System Architecture & Project Workflow

The application strictly adheres to a decoupled 3-tier microservice architecture:

Layer Technology Hosting Target Responsibilities
Frontend React 19 + Vite + TailwindCSS Vercel Single-Page Application (SPA), quote calculator form, interactive SHAP visualizer, PDF report generator.
API Gateway / Backend Node.js + Express Render JWT Authentication, rate limiting, MongoDB persistence, ML service proxy with cold-start retry engine.
ML Microservice Python + FastAPI + Uvicorn Render High-performance inference engine running XGBoost Regressor and SHAP TreeExplainer.
Database MongoDB Atlas Cloud MongoDB Persists user accounts, hashed passwords, and historical prediction records.

End-to-End Prediction Workflow

  1. User Input: User inputs 20 health and demographic metrics on the React frontend.
  2. API Request: React sends an authenticated POST request to Express backend (`/api/predictions`).
  3. Cold-Start Detection & Retry: If FastAPI ML Service is sleeping, Express automatically pings and retries up to 15 times (every 3 seconds) while frontend shows smooth stage messages (*"Preparing AI prediction...", "AI service is starting..."*).
  4. ML Inference: FastAPI processes feature transformations, executes XGBoost prediction, and computes SHAP feature attributions.
  5. Persistence & Audit: Express saves the result to MongoDB Atlas and returns the quote + SHAP breakdown to React.
  6. Render & Export: React displays interactive risk cards, waterfall plots, and enables one-click PDF report exports.

4. Machine Learning Models & What Each Component Does

🤖 Model 1: Tuned XGBoost Regressor (Primary Inference Model)

Role: Predicts the exact annual medical insurance premium in USD ($).

  • Algorithm: eXtreme Gradient Boosting (XGBoost) Decision Trees.
  • Cross-Validation Accuracy (R²): 87.99% (0.8799)
  • Mean Absolute Error (MAE): ~$2,064.14 USD.
  • Artifact File: insurewise_model.joblib (Loaded once on FastAPI startup).
🔍 Model 2: SHAP TreeExplainer (Explainability Engine)

Role: Calculates game-theoretic Shapley values to assign exact dollar cost contributions to each input feature.

  • Algorithm: SHAP (SHapley Additive exPlanations) TreeExplainer optimized for tree-based models.
  • Output: Map of feature attributions showing positive shifts (+ Quote) in green and negative shifts (- Quote) in red.
  • Primary Actuarial Drivers: Smoker status, Age, BMI, and Chronic Diseases account for >85% of total quote variance.
⚙️ Custom Transformer: BloodPressureExtractor

Role: Custom Scikit-Learn transformer registered during model training.

  • Function: Parses string blood pressure values (e.g. "120/80") into numeric systolic_bp and diastolic_bp float columns during pipeline execution.
